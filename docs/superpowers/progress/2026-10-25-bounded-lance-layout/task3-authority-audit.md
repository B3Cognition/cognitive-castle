# Task3 authority and resolver audit

Static architecture review against the accepted Task2 APIs, Task3 plan, current bulk store and persisted-replay implementation. No product edits, tests, database/source reads, native engines or probes. This identifies required bindings; it does not approve an unimplemented schema or grant runtime.

Root has accepted the compact authoritative ID-claim approach and trusted closed qualification registration. The sole writer will provide the concrete schema/operation delta for review. Preserve schema4 compatibility and original registration/source/cursor/ACK semantics; exact192/256MiB, read2s/write3s and the same absolute5s session remain unchanged.

1. **Qualification is authority, not an opaque hash alone.** Task2's envelope has only qualification_hash and expansion totals. Before the first tick, a trusted host must register/resolve a closed hash-bound descriptor covering generation identity, selected-partition geometry/artifact depth/entry/file/retained-byte limits, append/maintenance charges, scan settings and bounded remote acquisitions. The request may reference that authority; it must not select budgets or alter the original registration. Self-consistent caller metadata is not independent qualification.

2. **Registry and claims precede native mutations.** Authoritative partition descriptors must bind derived numeric ID/path, real generation/parent/directory identity, pinned version/geometry/index state, active/sealed state and unresolved mutation. Separate compact authoritative ID claims from rebuildable route rows. Retain each original ID/home/intent claim after publication; create all possible new claims before append. Task2 currently reserves missing derived routes without absence authority: Task3 must bridge this by checking a complete registry epoch before new-ID reservation, then invalidating coverage for the pending mutation atomically. An own pending reservation is not evidence that no older row existed. Unknown commit/index acknowledgment freezes the same reservation for exact reconciliation.

3. **Narrow global-absence guarantee.** A retained claim plus missing route is unavailable, never absent. A claim miss is usable only against the trusted complete registry epoch with no unresolved publication/rebuild. Bootstrap authority requires a verified empty registered namespace or complete bounded enumeration of all trusted pinned partitions plus original pending intents. A boolean, stored count or missing table is insufficient. Claims/registry/migration jobs are trusted protected-restoration prerequisites: this does not claim detection of coherent corruption of authority and derived data together. Root explicitly accepted this narrower guarantee; no cryptographic database framework is proposed.

4. **Reconstruction is derived-index work only.** Fixed pages bind registry epoch, partition identity/version, exact expected physical cursor, bounded row IDs/kinds/hashes/receipt/gate references and next cursor. Require contiguous monotone coverage, exact idempotent duplicate-page equality, row/version bounds and refusal on gaps, conflicting IDs or stale pins. All registered partitions and original pending intents must reconcile before complete coverage. A native owner marker alone cannot publish a gate or advance the source frontier; rebuilding never performs a source ACK or records partial owner/hash proof. Reserved-but-unwritten claims remain accounted rather than disappearing from a physical-only scan.

5. **Fixed retry and witness binding.** Regenerate the exact pending source window and full intent, preserving its selected home, source/digest/expected-ID set and reservation. Validate an actual under-lock persisted replay against logical generation identity, qualification/envelope, partition/registry pin and exact pending intent. The existing persisted_replay helper calls the immediate directory parent `generation`; for generation/exact/partitions/N that parent is not the logical generation. Keep physical parent/directory identities and explicitly add the logical binding. Fresh append still needs independently reopened persisted proof; current verified replay may complete under the reviewed conditional protocol. Owner/LIVE checks use the witnessed version and the same deadline.

6. **Exclusive namespace and selected paths.** Global absence is unsound if an ordinary BulkExactStore call can write directly into a registered partition without claims/epoch changes. Preserve legacy behavior outside the registered namespace; registered writes must go through the bound facade. Validate trusted generation, fixed ancestors and selected descriptor directly, then the full bounded selected partition artifacts before open and again under the writer lock. Do not call the legacy recursive root walk over all partitions. Do not trust caller-provided partition paths or route objects.

7. **Resolver and owner span are real implementation gaps.** BulkExactStore candidate existence and _verify_batch use module-level lookup_many; overriding only _find_many does not route reuse. Add narrow default-preserving hooks covering existence, receipt-proof fetch and original owner/visibility checks. Always compare actual canonical bytes/provenance and original first-owner membership, refusing foreign staging. Keep one pinned home plus at most one remote handle; close before switching, charge actual remote acquisitions/reopens and cap returned rows. Task1 OrderedBulkExactStore explicitly accepts one owner and resolve_reused={} and cannot be reused as a multiowner scan. A bounded registered span requires one active owner per writable partition until final ACK/freeze, or an independently qualified bounded span list; one writer at a time alone does not prevent interleaving jobs. No whole-owner body cache, interactive all-partition repair scan, sorting or persisted SHA state.

Remaining review: writer's concrete minimal schema/operations and authority bootstrap, then focused code and separately prepared native evidence. Task2 metadata PASS does not establish any of these native/reuse/absence properties.
