The fixture is unexecuted and not frozen. Root accepted these three findings and owns their corrections:

1. **Temp admission has no retained headroom.** The proposal sets working_temp_bytes and envelope.temp_bytes both to 4 MiB. Current facade `_temporary_charge` accounts the retained temp tree (including its directory) and then reserves working_temp_bytes. Any nonzero retained size exceeds that equal whole ceiling. Root will explicitly separate 4 MiB working allowance, 4 MiB retained spill and 1 MiB retained structure before freezing; these remain proposed test charges, not production authority.
2. **The refusal blacklist can falsely pass later negative cases.** `_record` omits real guard reasons including system_pressure_unavailable, parent_memory_limit and background_preempted. An expected unavailable result could therefore pass on a resource/admission failure with one fresh metric. Root will use explicit per-call expected reasons, defaulting to None; deliberately lost responses/deadlines need their own exact allowance. The current happy test's final status checks already prevent that false pass there.
3. **Happy-path proof assertions are incomplete.** Import outcome labels and a final receipt alone do not assert that both imports had identical arguments or that the real owner and original LIVE proof reads occurred, with the same intent/version, before ACK. Root will assert observed call order, both import arguments, manifest/result equality and shared replay context. Expected digest will come independently from `prepare_remember` over the known original nine-chunk fixture input/provenance, rather than only from the import arguments being tested. These assertions need no extra native calls.

Calls are charged before dispatch. The host imports no storage engine; every publication uses one actual background SemanticSession and its original absolute deadline. The observer forwards remaining and _ready. The existing source fixture has its separate 128/192 MiB, 2s setup profile.

Since the host currently constructs the body and hash together, final independent trust still requires root's frozen script/constant construction and launch binding; equality alone is not that seal. Proposed 2 MiB growth/16-entry charges resemble prior scoped allowances, but the 4 MiB file and working-temp limits have not inherited Task1 native qualification. Actual setup/census/temp/output bounds and the final call schedule remain prerequisites. Missing first-owner APIs are expected implementation work, not a new skeleton defect.
