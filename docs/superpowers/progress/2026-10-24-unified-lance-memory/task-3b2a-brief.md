## Durable metadata and queue operations

Allow one immutable registration and **one prepared pending interval** per job. IDs bind a versioned domain, registered destination generation, full source binding, stable packing/coordinator version and original `cursor_before`. Time, retry number and a new temporary path are not identities. Store only metadata and references:

| Record | Required content |
| --- | --- |
| Job | Job/source/destination identities, registered source descriptor/binding, packing/coordinator version, verified staging cursor, completed-owner frontier, pending intent reference, separate counters/coverage and terminal/refusal state. |
| Prepared interval | Intent/batch ID, binding, exact `cursor_before/cursor_after`, request digest from actual `bulk_exact_codec.validate_batch`, bounded entry/finalization counts, expected owner manifest hashes/classification/member counts, finalization counters and source coverage. No durable verification offset, phase journal or proof-page accumulator. |
| Committed owner reference | Job/source binding, owner ID/key, published manifest hash and text/membership/scope/descriptor summaries, member count, observed proof version, source phase/key, explicit `live/history/audit` classification and semantic disposition. Key it idempotently by committed owner identity. |

Never persist `entries`, canonical text, field pages, caller/provenance JSON, exact scope/metadata/descriptor/audit content or a serialized export response. Original live receipt IDs (≤9), hashes, lengths and source primary/cursor keys are references; do not copy corpus-wide membership into one row. Original live receipt content remains canonical in Lance at its established namespace/key. Enforce strict byte/count/schema bounds and fixture sentinel checks for bodies in all queue rows.

Minimum private queue methods, routed as additive `queue_migration_*` operations through the existing worker:

1. `migration_open`: idempotently register immutable source/destination/job binding; changed binding conflicts. Registration grants no movement authority.
2. `migration_state(job_id)`: return one compact job and pending interval, plus bounded prior ACK identity/result needed to resolve a lost ACK.
3. `migration_prepare(job_id,expected_cursor,intent)`: in one transaction compare the prior verified staging cursor and install at most one interval. Identical retry returns its original result, changed intent conflicts. No frontier/counter advance.
4. `migration_ack(job_id,intent_id,verified_summary)`: after current-tick verification, atomically consume the exact pending interval, advance allowed cursors, update counts and create distinct owner references. Preserve bounded idempotent ACK identity/result so response loss never duplicates counts/references. Wrong pending identity or prior cursor conflicts. No new CAS lease or durable proof-progress operation.

Queue rows cannot independently prove Lance publication. After interruption, ignore any remembered partial verification and perform the complete required checks again. Serialized admission and guarded transactions protect these operations; do not add a lease/revision protocol unrelated to a demonstrated requirement.

## Publication and restart verification

One exported slice contains at most one source owner, possibly a staged interval of it. Retain the existing byte/count bounds and real ASCII request/response frame accounting. Never re-pack an already prepared interval differently after an upgrade.

1. **Recover before selecting later work.** Read the job. If pending, regenerate from that interval's exact `cursor_before`; otherwise export from its verified staging cursor. Validate source binding, returned cursors, phase/classification, counts, entries/finalizations and frame limits. A pending interval must regenerate identical `cursor_after`, expected owner manifests, counts and actual batch digest. A changed binding/body/packing is a stopped conflict, not a new attempt that skips the old interval.
2. **Prepare before any destination write.** Derive deterministic batch ID and digest using real `validate_batch`, then durably prepare metadata. A prepare refusal means no destination write. The first exported bodies may remain ephemeral and be reused **in the same tick after successful prepare**; do not redundantly re-export them. If the tick ends, discard bodies and regenerate next tick from the immutable source.
3. **Import or replay the identical batch.** Call actual `import_batch(batch_id,source_binding,entries,finalizations)`. Compare compact `{status,state,receipt_id,digest,records,published_owners,entries}` against intent and regenerated body. Changed request-key reuse must conflict. Initial append success alone is insufficient for ACK because it is not independent durable verification.
4. **Verify durable storage in the current tick.** Prefer a checked **existing identical `import_batch` replay** as the single recovery path. Existing replay runs full `_verify_batch` and compares the exact expected proof-ID set against regenerated entries/finalizations/original live receipt IDs. Native `_verify_batch` checks every proof entry, hashes/kinds/counts, owner/binding and original live receipt proof internally. A generic `ok` that could be first append does not establish independent verification: if it was not demonstrably an existing replay, issue the next identical replay, or real `bulk_receipt` after the confirmed append, before ACK. The latter also performs full-worker `_verify_batch`; compare its source-bound request digest/identity/counts against the prepared interval. Its response displays only≤16 proof entries, but verification covers all entries inside the worker. Do not page through host proof entries merely to duplicate that check. Keep expected-ID-set comparison in the actual identical-replay boundary; never replace it with incoming physical-row hash comparisons or a custom host proof protocol.
5. **Check final owners and original live receipt.** For finalizations, `bulk_owner(owner,version?)` must return the expected `published_owner` manifest exactly, including source binding, whole/member/field summaries and `live`. Pin subsequent checks to its dataset version where the API supports it. For live owners verify original exact `receipt(namespace,key)` and compare its digest/original receipt with the regenerated finalization. Preserve normal old retry semantics. For stage-only intervals there is no published-owner lookup. Reused visible legacy `record` rows may differ physically from incoming `bulk_record`; compare canonical semantics/worker-verified expected IDs, never naïve incoming physical row hashes. No whole-owner hydration in host.
6. **ACK only after all required checks in that same tick.** Atomically update coordination. A stage-only interval advances **verified staging cursor**, while completed-owner frontier stays at the preceding finalized unit. A finalized interval advances completed-owner frontier and creates the correct distinct reference/counts. Original SQLite keyset frontier is not a raw native archive cursor or coverage proof. On ACK response loss, read/replay its same identity/result; never generate a new batch ID or recount an owner.

No durable partial-proof phases: if source regeneration + checked existing replay + required owner/live checks + ACK cannot complete in the fixed 5 s tick, retain the same pending interval and restart verification on a later tick. Measure the cold path. Repeated inability is a reported qualification gate, not permission to persist a proof framework, omit verification or widen limits. Initial staging/write may have happened in an earlier tick. Postprepare/prewrite and postcommit/preACK interruptions are required fixtures.

Lost destination response leaves publication ambiguous until durable verification. `not_initialized/not_found` never means completion; preserve frontier and allow only identical replay under the fixture boundary. If the source cannot regenerate, preserve committed artifacts and report recovery unconfirmed. Preemption/deadline success arriving late is not ACK authority.

A successful **no-content `done` transition** uses a separate scan-exhaustion ACK with no pending interval and all earlier units acknowledged. 3a rejects empty batches: do not fabricate an empty import/receipt or fake historical owner. Record `snapshot_export_exhausted`; never infer exact corpus completeness, resolved gaps or semantic completion. Orphan refusal cannot receive that ACK.
