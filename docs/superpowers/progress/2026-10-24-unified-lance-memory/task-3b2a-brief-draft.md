## Minimal durable contract

One immutable registration and one pending interval per migration job. Deterministic IDs include versioned domain, destination generation identity, complete source binding and original export cursor. Never derive an ID from elapsed time, retry number, temporary path or returned batch row counts. Use stable queue request IDs/CAS revisions so a lost coordination response is replayable.

Proposed metadata records (field names may follow local conventions; freeze exact schemas/tests):

| Record | Allowed durable fields |
| --- | --- |
| Job | job ID, source descriptor/binding, registered destination generation identity, packing/coordinator version, revision, verified staging/export cursor, completed-owner frontier, pending intent reference, separate coverage/counts, terminal/refusal state. Source registration paths and primary keys are metadata; raw manifest/descriptor/scope/text strings are not copied here. |
| Pending interval | intent ID, job/revision, `cursor_before/cursor_after`, deterministic batch ID, `validate_batch` request digest, exact bounded entry/finalization counts, expected proof IDs (batch-bounded references), expected owner IDs plus manifest hashes/classification/member counts, finalization counters, source coverage, verification offset/version, stage. Persist no `entries`, field pages, canonical text, provenance/caller JSON or exact audit payloads. |
| Verified owner reference | job/source binding, owner ID/key, published manifest hash, text/membership/scope/descriptor hash summaries, member count, destination proof version, source phase/key, classification `live/history/audit`, and semantic disposition. Primary key includes committed owner identity; bounded counters are idempotent. Preserve original live receipt through Lance; do not copy its body or replace its namespace/key. |

Original live receipt IDs (≤9), proof IDs (≤batch cap plus owner/legacy receipt), hashes, lengths and cursor keys are allowed references, not bodies. Keep strict byte/count/schema caps; never store all corpus IDs in one row. A hash does not make a hidden body field permissible. Check queued JSON for exact text, metadata, scopes, caller and descriptor sentinel strings in fixtures.

Queue operation minimum:

1. `migration_open` registers immutable source/destination binding idempotently; same ID with changed binding conflicts. This prepares metadata only and grants no movement authority.
2. `migration_state(job_id)` reads one compact job/pending interval; no unbounded job/history list.
3. `migration_prepare(job_id,expected_revision,intent)` atomically checks the prior verified staging cursor, installs at most one pending interval and increments revision. Identical retry returns its original result; changed intent conflicts. It never advances a frontier.
4. `migration_verify(job_id,intent_id,expected_revision,proof_progress)` persists bounded receipt-page/owner-verification progress with exact digest/binding/version, never a caller assertion that publication happened. Host gets progress only from existing supervised exact operations; no public route exposes these coordination operations.
5. `migration_ack(job_id,intent_id,expected_revision,verified_summary)` atomically consumes the verified pending interval, advances its allowed cursor(s), updates exact counters and creates owner references. Same completed intent replays once; no duplicate counts/outbox row. Persist a bounded last ACK identity/result or immutable interval row for lost-ACK recovery.

These are internal methods routed through the existing fixed queue worker. Queue metadata cannot independently prove Lance publication; coordinator must re-obtain durable proofs after an interrupted or untrusted verification state. Recovery uses one bounded pending interval, not a corpus scan. Read operations receive fixed 2 s queue caps; mutations remain at most 3 s, all inside the tick.

## Interval lifecycle and verification

Use a small durable sequence such as `prepared → receipt_verifying → owner_verifying → acknowledged`. There is no need to finish it in one tick.

1. **Recover first.** Read job/pending state. If pending, resume/reconcile that exact interval before exporting later work. If none, export from the job's verified staging cursor through the fixed source stage. Validate binding, exact `cursor_before`, returned cursor shape, frame sizes, entry/finalization schemas and counts. Source `phase_complete` only says a finalization was emitted. `complete` only exhausts export phases; neither is destination confirmation.
2. **Persist before native write.** Derive batch ID from job/binding/packing and `cursor_before`; derive digest with the actual `bulk_exact_codec.validate_batch`. Persist intent including exact returned interval and bounded proof identity expectations. If coordination prepare fails, perform no destination write. If source consumes the tick, discard its ephemeral bodies and repeat the same immutable export next tick.
3. **Regenerate, compare, import.** A later tick re-exports the recorded `cursor_before`, validates that `cursor_after`, phase/counts, expected owners and body digest are identical, then sends the actual bounded `import_batch`. Never re-pack an old interval differently after an upgrade; incompatible packing/adapter version is a stopped job requiring an explicit new reviewed attempt. Identical replay uses the same key/body; conflicting reuse fails closed. Bodies remain only in the current bounded host frame and workers.
4. **Verify durable batch.** Import's compact result `{status,state,receipt_id,digest,records,published_owners,entries}` must match expected identity/digest/counts/state, but does not itself advance coordination. Call real `bulk_receipt`; it independently runs `_verify_batch`, returning the same compact fields plus ≤16 `{id,physical-row-hash}` proof entries, `next_offset/complete/version/lookup`. Source binding mismatch conflicts. Compare complete expected proof identity coverage/order without assuming incoming physical row hashes: reused visible legacy `record` rows legitimately have a different physical encoding from incoming `bulk_record`. The existing worker validates actual stored hashes/kinds/counts. Require no missing/extra/duplicate IDs, monotonic offsets and one dataset version across proof pages. Persist bounded verification offset; `stale` restarts that proof pass at current version, not publication. No custom resumable SHA state is needed for this bounded reference list.
5. **Verify owners and original receipt.** For each expected finalization, real `bulk_owner` must return the exact manifest hash/binding, member/field hashes and `published_owner` state at the pinned verification version. Original live receipts must also survive the existing exact `receipt(namespace,key)` verification and match digest/original receipt from the regenerated finalization; this can consume another tick. `bulk_receipt` already invokes owner/legacy proof validation, but make the coordinator's acceptance rule explicit rather than inferring success from publication count. Do not hydrate an entire occurrence or reread all membership pages in host.
6. **ACK atomically.** Once proofs are complete, update queue cursor/counts/references in one transaction. A staged batch may advance **verified staging cursor only**; the completed-owner frontier remains at the preceding finalized unit. A finalized unit advances the export completed-owner frontier and creates its distinct reference. Neither frontier is a raw native archive cursor or proof of historical coverage. ACK response loss reads/replays the same intent/ACK; never issues a new batch ID or increments counts twice.

No-content successful transition to source phase `done` is a separate verified **scan exhaustion** ACK: 3a rejects empty batches, so do not manufacture an empty import/receipt. It requires no pending interval and all preceding owner units acknowledged. This marks `snapshot_export_exhausted`, not `exact_complete`, real coverage complete, or semantic complete. Orphan refusal does not receive this ACK.

Lost response after destination commit is recovered by its deterministic receipt; a missing receipt leaves original committed frontier and allows identical regeneration/replay only under the appropriate write gate. `not_initialized/not_found` is absence, not completion. If proof exists but source is no longer re-readable, keep committed output and mark recovery unconfirmed; do not advance from counts or a bare compact response. An exhausted tick, preemption or ambiguous write never acquires a second admission/session to finish work.

## Coverage and semantic-owner references

Counts come from acknowledged finalizations, not export attempts, native physical rows or stage writes. Preserve `live_owners,historical_occurrences,audit_owners,members,gaps,repaired_gaps,pending_stages,orphans` separately, and retain source coverage limitations. AUDIT is the existing 3b1 domain-separated zero-member descriptor owner with `metadata_id=null/live=null`: never increment historical occurrences for it. Pending-stage descriptors reference retained protected source recovery state, not canonical staged text/carry.

Only verified live/history owners with members produce `semantic_pending_owner` references. Empty historical occurrences are exact real occurrences with an explicit no-members semantic disposition. AUDIT, gaps and pending-stage descriptors are nonsemantic audit work; repaired-gap audit publication cannot independently count its occurrence again. Profile/scope availability remains explicit pending/undecided: no substitution of current Task 2 nonempty fixed scope shape for long/absent/conflicting source facts. Later 3d reads owner membership in bounded pages and validates exact hydration/exposure before group registration. This task neither enumerates all members into an outbox nor claims any vector coverage.

Do not derive raw archive continuation from this SQLite keyset frontier. 3b2b/3c must reconcile the original historical attempts and their raw cursor identities across all shards and gaps/repairs. New snapshot generations require their own bindings and later delta reconciliation, including scope-only changes without new chunk rowids.
