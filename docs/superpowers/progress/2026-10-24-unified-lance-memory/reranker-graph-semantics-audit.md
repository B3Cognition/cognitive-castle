## Confidence, remaining boundary, and smallest next step

Confidence is high that the **serialized** graph's architecture, indexing, broadcasting and normalization axes contain no discovered cause of this fixture's ranking failure. This is a targeted static comparison, not an ONNX checker, exhaustive formal proof, or numeric layer-output comparison.

The historical exporter source is **not fully pinned by available provenance**: `MCFG` records `transformers_version=4.30.0`, whereas the installed source is 5.6.2, and graph metadata identifies PyTorch 2.0.1 without a Transformers exporter commit or export flags. Save-time config metadata alone does not establish the exporter version. Installed source additionally dispatches through `config._attn_implementation` (`XLMR:239–254`); its selected eager/SDPA kernel path was not observed. Thus the comparison supports architectural agreement with official config and inspected source, not exact parity with an identified historical Torch execution.

Static files cannot identify a particular wrong kernel or prove its numeric equivalence. No suspicious individual serialized node justifies graph surgery.
