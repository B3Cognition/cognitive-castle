No native/model/database operations, converter execution, or product edits. Installed commit and stopped progress (483,895/519,641) are supplied context, not independently measured here. - **Live exact publication is a durable protocol, not only `remember` substitution.** [fast_memory.py:222](../../../cognitive_castle/fast_memory.py#L222) derives request digest from namespace/request/text/caller, makes UTF-8 chunks of at most 8 KiB with character offsets, derives `memory:` IDs from digest/chunk ordinal, and commits chunks, FTS and idempotency receipt together (lines 237–290). [memory_ingest.py:352](../../../cognitive_castle/memory_ingest.py#L352) binds each piece to source/generation/record hash/block hash/exact record and block offsets, advances pending cursor only after successful receipt (lines 368–406), then advances source offset/checkpoint (432–434). Minimal boundary: a canonical Lance writer preserving those existing IDs and exact caller data, with idempotent commit token and receipt validation; SQLite may hold request digest, IDs, source checkpoints and queue state, but cannot announce success before the matching exact Lance generation is durable and recoverable. Enqueue semantic work keyed by committed ID/input hash/profile without loading a model in capture. Recover a Lance commit whose coordination acknowledgement was interrupted; conflicting reuse of a request must remain `conflict`.

- **Capture scope currently depends on a global SQLite `rowid` watermark.** [memory_capture.py:141](../../../cognitive_castle/memory_capture.py#L141) finds chunks by JSON source/generation, inserts immutable scope mappings from `chunks`, and restricts new assignment by `rowid > scope_attempt.after_rowid` (178–206); `_prepare_scope` records `MAX(rowid)` before ingest and replays interrupted attempts (223–242). Minimal change: replace the watermark with durable attempt/commit membership listing the exact successfully published chunk IDs, plus source generation, record offsets and observed source identity. Keep assignment-once semantics, transcript-metadata precedence over host hint, first-workspace offset, conflict boundaries and retry reconciliation. Derive scoped/unscoped counts from committed Lance membership; a Lance physical row address must not replace the live SQLite sequence assumption.

- **Context bypasses ordinary reads through SQL joins and must use a shared scope/hydration boundary.** [memory_context.py:14](../../../cognitive_castle/memory_context.py#L14), [memory_context.py:40](../../../cognitive_castle/memory_context.py#L40) and [memory_context.py:273](../../../cognitive_castle/memory_context.py#L273) directly join `capture_chunk_scopes`, `chunks`, and `capture_sources`, test current generation/role, and sort by source time/record/chunk offsets. Work-state updates bind exact hashes to workspace-authorized IDs and use revision/idempotency coordination (134–180); historical fallback already calls common `scoped_source` (104–111). Minimal change: make both live and historical references use provider methods for scoped candidates and exact hydration; retain SQLite only for host work state/revisions/receipts and bounded scope coordination. Preserve pinned old references, current-generation selection, reserved user-intent slots and 8 KiB output bound. Unified context also introspects exact SQLite index SQL and joins occurrence membership: [unified_memory.py:537](../../../cognitive_castle/unified_memory.py#L537); replace those assumptions with a bounded indexed-scope capability and explicit pending coverage.

- **Remaining historical rows need a pinned streaming adapter plus original vector mapping.** [memory_history.py:629](../../../cognitive_castle/memory_history.py#L629) scans immutable version/fragments, deletion-aware offset, batch size one, disabled readahead and checked `_rowaddr`; it excludes `vector` (650), materializes each selected scalar (678–681), and explicitly leaves oversized decode/offset-pushdown qualification unresolved. Occurrence identity is SHA-256 of archive/snapshot/version/fragment/physical address (1382–1385), distinct from repeated drawer alias. `_commit_row` bypasses `remember`: it directly inserts chunks/lexical/occurrence/alias/attempt receipts in one SQLite transaction ([memory_history.py:1371](../../../cognitive_castle/memory_history.py#L1371), 1457–1503). Minimal change: a resumable provider iterator/export contract for only the remaining pinned rows; preserve original cursor identity and all non-vector columns/metadata byte content, and separately bind retained original vectors to their original whole-row input and verified model profile. Preserve existing chunk IDs `hash([occurrence, character_start])`; never relabel a whole-row vector as an individual chunk vector. Reconcile already converted occurrences before selecting a new migration checkpoint; do not resume the stopped converter merely to populate the new store.

- **Oversized rows require page staging and atomic visibility, not repeated whole-row append.** Schema and state are explicit at [memory_history.py:807](../../../cognitive_castle/memory_history.py#L807): `history_staged_rows` stores exact metadata/columns, carry and copy/hash/publication progress; `history_staged_chunks` stores exact text. `_stage_page` publishes deterministic 8 KiB pieces and page progress transactionally ([memory_history.py:1776](../../../cognitive_castle/memory_history.py#L1776)); `_stage_hash` checks contiguous offsets, all chunk IDs/hashes, total bytes/characters and full expected hash (1846–1877). `_stage_publish` currently rereads every piece and copies it into `chunks`/`lexical` in one transaction, adds occurrence membership, writes `history_attempts`, and deletes staging before advancing the job (1880–1935). Minimal change: stage exact pieces/carry/descriptors in Lance under an unpublished occurrence generation, retain only coordination references/counters/hashes in SQLite, stream integrity verification, and expose pieces only after a durable whole-occurrence manifest/commit receipt. Use bounded append batches with persisted publication position; make final visibility/cursor advancement idempotent so deadline or worker death cannot require a larger all-row transaction. Preserve hash/publication inflight markers and distinct retry counters ([memory_history.py:2041](../../../cognitive_castle/memory_history.py#L2041)); recovery must consult durable canonical receipt before advancing the precise source cursor ([memory_history.py:2179](../../../cognitive_castle/memory_history.py#L2179), 2249–2279). No `history_parts` symbol exists in the eight audited files; its current equivalent is `history_staged_chunks` plus `history_occurrence_chunks`, not an assumed extra table.

Minimal change: canonical Lance occurrence/descriptor records and membership, preserving exact metadata strings, all hoisted columns, independent hashes/lengths and alias multiplicity. Keep full scope values: historical registry columns override metadata, then bounded caller fields; long workspaces cannot be reconstructed from the small caller envelope ([unified_memory.py:414](../../../cognitive_castle/unified_memory.py#L414), 584–606). Keep the top-level source descriptor and both paging fields through every adapter; flattening only `id/text/provenance` loses this contract.
