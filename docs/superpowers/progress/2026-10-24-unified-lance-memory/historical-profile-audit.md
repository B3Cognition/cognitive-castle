# Historical embedding profile: static evidence audit

2026-10-24. Read-only inspection of repository code/history, small local configuration/cache metadata, and existing diagnostics. No models/native libraries loaded, palace opened, vectors read, tests run, downloads made, or user text extracted. Only this report was written.

## Conclusion

There is stronger circumstantial evidence for the multilingual MiniLM profile than dimension and the stored short identity alone: the current private configuration explicitly selects that model; a historical config default explains the exact short identity; historical code consistently requests L2 normalization; and the single locally cached model snapshot provides concrete tokenizer, mean-pooling and 128-token settings. **None binds that revision or generation path to the archive's historical vectors.** Historical compatibility remains unproven.

Empirical qualification is technically possible without discarding stored vectors. It can establish numerical/operational compatibility for measured rows and retrieval behavior under a pinned candidate. It cannot recover an absent generation receipt or prove one uniform generating revision for every row from a sample. The approved specification explicitly requires a verified historical model contract; if that remains unavailable, its completion path is verified re-embedding of required semantic units. Empirical acceptance of unknown provenance as a replacement for that requirement would need an explicit design decision.

## Cached candidate contract

Base: `~/.cache/huggingface/hub/models--sentence-transformers--paraphrase-multilingual-MiniLM-L12-v2/snapshots/e8f8c211226b894fcb81acc59f3b34ba3efd5f42/`. This is the only snapshot directory observed; `refs/main` contains that revision. Cache presence neither dates historical inference nor proves the archive used those bytes.

- `sentence_bert_config.json`: `max_seq_length=128`, `do_lower_case=false`. SHA-256 `70f4448f31320443fe3557cacea5abf2dcc4915dda8c80646bec9f3bb0aa5a1f`.
- `1_Pooling/config.json`: 384-dimensional mean-token pooling enabled; CLS, max and mean-sqrt-length disabled. SHA-256 `4be450dde3b0273bb9787637cfbd28fe04a7ba6ab9d36ac48e92b11e350ffc23`.
- `modules.json`: Transformer then Pooling; no separate Normalize module. Application code supplies L2 normalization. SHA-256 `8f4b264b80206c830bebbdcae377e137925650a433b689343a63bdc9b3145460`.
- `tokenizer.json`: Unigram model, precompiled normalizer, whitespace then Metaspace pre-tokenization, `<s>`/`</s>` template. Serialized truncation is longest-first at 128, stride 0; padding is batch-longest/right with pad ID 1. SHA-256 `2c3387be76557bd40970cec13153b3bbf80407865484b209e655e5e4729076b8`.
- `tokenizer_config.json`: `PreTrainedTokenizerFast`, nominal model maximum 512, `do_lower_case=true`. This differs from the sentence-transformer lower-case setting. Do not interpret one JSON field alone as the executed preprocessing contract; verify token IDs against the reference sentence-transformer path, especially case, accents, whitespace and Unicode. SHA-256 `5036ea374ffedd706e3bef33e2e0d6953cb868ef8a490e76e32ba0faa37a6b9b`.
- `config.json`: 12-layer `BertModel`, hidden width 384, architectural maximum 512 positions. The sentence-transformer effective window is 128; architectural capacity does not establish 512-token historical coverage.
- `config_sentence_transformers.json` records export-time versions ST 2.0.0, transformers 4.7.0, torch 1.9.0+cu102. These are artifact creation metadata, **not installed historical runtime versions**.

The spec records official ARM64 qint8 ONNX bytes pinned to the same revision, size 118,412,398 and SHA-256 `783fea82d71a58179b830a4dbd2d58447e640609e98eedf9ffa12622d375a672`. This audit did not reopen/hash the model binary. Quantized ONNX inference is a changed numeric implementation; sharing tokenizer/pooling/revision does not prove compatible scores or rankings.

## A defensible empirical qualification, if separately authorized

1. Read bounded exact row/vector pairs from the already pinned snapshot through a strictly read-only worker. Bind archive ID, version and physical row address, canonical occurrence and exact input hash. Never sample by repeated drawer alias alone. First check finite/nonzero vectors and norm distribution; unit norms support L2 normalization but do not identify a model.
2. Compare the same original row inputs under the pinned reference floating-point sentence-transformer profile and the qint8 candidate. Separate stored-to-reference differences from reference-to-qint8 differences. Check token-ID parity and mean pooling/L2 behavior on multilingual, case/Unicode, empty, short, and over-window examples. A quantization tolerance must be calibrated and declared; cosine similarity alone cannot certify generating revision.
3. Stratify archive measurements across physical fragments/ingest periods, source types, languages, text lengths, repeated aliases and suspected model transitions. Long historical rows may embed only their first 128 tokens. Their old vector cannot stand in for every new window or policy-authorized fragment; additional windows require new vectors even if the old first-window vector qualifies.
4. Evaluate held-out real retrieval with new candidate query vectors against retained historical vectors, including mixed new/history searches and relevance beyond the first window. Record failures and coverage, latency and bounded resource results. Synthetic candidate self-search does not measure this.
5. Preserve vectors regardless of outcome. Sample success qualifies only sampled evidence. For per-row reuse under an empirical policy, retain individual comparison receipts and quarantine/re-embed failures; an all-row comparison itself requires generating reference/candidate vectors, so its cost advantage over re-embedding must be measured. Unknown cohorts cannot silently inherit sampled compatibility.

Under the current spec's identity rule (lines 101-120), successful numerical similarity is supporting compatibility evidence, not a substitute for the missing historical revision/input contract. Use a distinct label such as `empirically_compatible_unknown_origin` only if that policy is explicitly accepted; never relabel it as `historical_profile_proven`. Otherwise preserve the old vectors and re-embed the required canonical semantic windows under the verified profile, with durable coverage receipts. No full re-embedding or archive probe was initiated by this audit.
