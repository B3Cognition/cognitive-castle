## Boundary and reusable code

Build two inactive adapters feeding the existing six-string `bulk-v1` codec: protected SQLite export and remaining pinned archive export. Keep source access in disposable supervised source workers and destination access in the existing supervised exact worker; do not open both storage engines in the host or stack source/destination workers concurrently. Source workers may reuse existing `MemoryStore._source/_provenance` and history validators directly without calling the converter. The host imports only pure codecs and exchanges bounded frames. `canonical_records.py` is already pure. `fast_memory.py` and `memory_history.py` import `sqlite3`; `history_projection.py` imports `memory_history`. Do not import those into the host to obtain a formatter. If a formatter truly must run there, **extract and share** the existing logic into a pure helper; do not copy its implementation.

Reuse `CanonicalRecord`, `_json`, `_hash`, `bulk_exact_codec.owner_id/page_id/page/validate_entry/validate_owner/entry_batches/validate_batch`. Reuse the behavior of history `_stage_header`, `_stage_caller`, `_chunks`, `_cursor_key`, `_valid_repair_cursor`, `_validate_inventory_receipt`, `_validate_original/_validate_snapshot`, and `NativeProjectedRow.header/bind_header/page/close` in their guarded source boundary. Never call `_commit_row`, `_stage_begin/_stage_page/_stage_publish`, `_index`, `_publish` or public converter `index/repair` operations. Their SQLite writes/catalog publication are not adapter primitives.

The new operator orchestration gets a root-selected fixed slice **no longer than 5 s**, with admission, interactive yield, pressure checks and descendant cleanup. This does not change existing profiles: native **source history** has approved `memory_runtime.HISTORY_RSS=512 MiB`, `HISTORY_TOTAL_RSS=640 MiB`, ordinary `HISTORY_DEADLINE=10 s`; the new route must set its own shorter fixed slice without changing that route. Source projection is not required to fit destination RSS. Destination exact native remains **192/256 MiB, reads 2 s/writes 3 s**. SQLite-only source work remains **128/192 MiB**. No limit is caller-selected; no profile increase is implied.

## Protected SQLite snapshot and read contracts

`protected_snapshot` below is a proposed private worker operation, not an existing API. Input is an operator-registered source/store ID and expected catalog/job binding, never an arbitrary caller path. It validates ancestors/no-follow/ownership/private modes/single links, uses a separate private admitted snapshot location, and reserves retained plus temporary bytes through Task 3c **before creation**. Use SQLite's consistent online backup/read-transaction mechanism in a supervised SQLite worker; honor current locking/busy/progress guards. The existing `MemoryStore._connect(write=False)` demonstrates read-only setup but its write path forces DELETE mode and must not be used to prepare this snapshot.

A source in WAL mode needs a committed SQLite view including WAL records. Do not copy only the main file, issue a source checkpoint, set journal mode, or set `immutable=1` on a changing WAL database. A naïve sequential main/WAL/SHM file copy is not a protected view either. The admitted backup can be incremental within a slice, but **a partial/restarted backup is not an exportable version**. On completion, close/flush/fsync the private snapshot and its directory, validate it again and bind its file identity and content/schema manifest. If a stable consistent view cannot complete under the fixed slice/profile, return pending/refused and qualify a narrower approach; do not hold an unbounded reader or widen limits. Synthetic WAL qualification must include a concurrent committed append and a killed backup.

Proposed compact result:

```
{status, snapshot_id, source_binding, manifest_hash, schema_hash,
 source_version, source_store_id, high_water, coverage_state}
```

`source_version` denotes the completed immutable protected view, not source mtime alone. `source_binding` is a domain-separated hash of a versioned manifest containing store/catalog/archive identity, protected snapshot identity, content/schema hashes and the immutable view boundary. It fits 3a's ≤1024-byte string; detailed manifest is paged evidence. File stat tuples detect replacement but do not prove content. Hash files/fields in bounded ordinary SHA256 passes; restart an interrupted pass, and mark a measured non-finishing pass as a qualification blocker. No custom resumable SHA state. Validate snapshot identity before and after each read; replacement, stale binding or malformed shape returns failure with unchanged committed frontier.

`export_slice(snapshot_id, source_binding, cursor)` returns `{status,source_binding,cursor_before,cursor_after,entries,finalizations,counts,complete,reason}`. `entries/finalizations` use 3a's exact codec contracts; counts are compact, not all IDs. `complete` means this bounded slice exhausted its requested phase/unit, never all historical coverage. Stable statuses distinguish ok/pending/busy/deadline/quota/stale/corrupt/unsupported without leaking source data in errors.

Cursor is a versioned private object bound to `source_binding`: `{phase,store_id,key,owner_key,member_ordinal,field,field_char_offset,field_byte_offset,batch_ordinal}`; unused fields are null. Whitelist phases and validate exact types/ranges. Live receipt key is `(namespace,request_id)`, historical occurrence key is `identity`, aliases use `(alias,identity)`, attempts/gaps/resolutions use `cursor_key`, scopes use original PK tuples, observations use `sequence`. Keyset page using the source indexes; no OFFSET scans, `.fetchall()` over an occurrence, giant Python IDs arrays or whole-occurrence string join. Chunk text/caller fields are read with validated byte ceilings; long fields use `substr(CAST(field AS BLOB),...,8192)` plus an incremental UTF8 decoder carrying ≤3 bytes, independent character offsets and exact hashing. SQLite `json_each`/joins still run under source RSS/deadline guards: bounded result count is not proof of bounded JSON decode or sort cost. Qualify plans on synthetic oversized IDs/membership before movement.

For live capture, source snapshot rowid/high-water is allowed only as a source-local export boundary. Keep capture running; later snapshots get new immutable bindings and reconcile appended receipts plus changed source/generation/scope/checkpoint facts. Old rows can gain scope mappings, so rowid-only deltas are insufficient. Use a later bounded snapshot inventory/merge; never call all live data complete until a known cutover boundary is reconciled. The stopped historical converter does not supply a delta feed.

## Streaming codec and durable checkpoint order

Owner key is the original occurrence ID, or a domain-separated hash of original live namespace/request ID (≤256 bytes). A stable `owner_id(owner_key,source_binding)` identifies publication; source binding includes the snapshot, so changing source versions cannot silently reuse a stage. Existing canonical IDs can be reused only after exact canonical comparison; public provenance never gains snapshot/destination fields.

Emit one exact record and one membership payload per chunk. Current candidate membership fields are `id,ordinal,start,end,bytes,hash,exposure,scopes`, where `scopes={first_page,hash,bytes,chars,pages}` binds the owner's full scope pages. Header offset/byte_offset for membership are the member ordinal; ordinary field pages have actual independent offsets. `bulk_record.digest` is owner ID, and its receipt is `{format:"bulk-v1",page:<membership-page-id>,ordinal}`. Hash ordered original chunk UTF8 for whole text and ordered exact membership payload UTF8 for membership SHA256. Field summaries are `{hash,bytes,chars,pages}` for metadata/columns/scopes/descriptor. Empty text has zero members and empty SHA256; empty fields have no illegal zero-byte page.

Production streaming must not call `prepare_owner` to collect a large unit. Maintain only current chunk/page, ≤8192-byte carry, bounded batch and scalar counters; emit via `page/validate_entry`, pack with `entry_batches` and validate the actual request with `validate_batch`. Candidate caps are 256 entries, 384 KiB decoded, 480 KiB encoded-body plus packing reserve within unchanged 512 KiB outer frame. Default ASCII transport escaping counts, including nested JSON. Source projection pages can be larger than an output frame: pick a fixed smaller projection window accounting for worst-case escaped output (for example ≤8192 source characters, then split into ≤8192 UTF8 chunks), not the old 131072-character maximum by default.

Resuming a partial occurrence cannot serialize a `hashlib` object. Re-read the immutable source in a bounded verification pass to reconstruct final text/membership/field summaries, or use source-provided expected whole/field hashes where independently validated; an expected membership digest still must be calculated over the exact canonical member payloads. Reuse ordinary streaming SHA256 and restart interrupted passes. Qualify both source summary pass within the new slice and destination whole-owner finalization within existing 3 s. If they repeatedly cannot finish, this is an explicit oversized-occurrence gate; do not guess hashes, hash page hashes, introduce a SHA framework, or advance the frontier.

1. Persist metadata-only intent: immutable source binding, cursor interval, deterministic batch key/body digest, expected counts/owner references, capacity reservation and phase. Do not persist encoded text/metadata entries in the outbox; regenerate them from the protected source.
2. Call `import_batch(batch_id,source_binding,entries,finalizations)`. Stable batch keys derive from binding plus original owner/phase/page interval; changed regenerated body conflicts. Preserve the same bounded packing configuration across retries, or explicitly start a distinct attempt before writing. Staging advances only a **staging replay cursor**, never source publication.
3. Verify the durable batch receipt (paged `bulk_receipt`) and each required `published_owner` (`bulk_owner`), including binding, expected hashes/counts and original live receipt. Compact result `{status,state,receipt_id,digest,records,published_owners,entries}` alone is not an invented full membership list. A lost acknowledgement first looks up the same durable proof; no blind cursor skip.
4. In one coordination transaction record receipt/version, move the committed source frontier only over verified indexed owners (or separately audited gaps), and enqueue semantic **references** keyed by committed owner/input binding/profile. Task 3d expands memberships later; no model call or vector claim here. Crash after destination commit but before this transaction replays/reconciles; crash before destination commit leaves original frontier. Capacity release awaits Task 3c artifact/receipt reconciliation.

Several small complete owners may share one append/finalization batch; a large owner spans staged batches and publishes only its final marker. Metadata-only attempts/gaps/coverage still need a canonical paged evidence destination before declaring their migration done. **The current owner shape has no standalone non-occurrence evidence owner contract**: freeze a minimal descriptor association or explicitly defer those units; do not invent fake empty historical occurrences to fit them.

## Remaining pinned archive continuation

Do not derive IDs from drawer alias, destination store/version, migration snapshot ID or row ordinal.

Continue only after migrated attempts/occurrences/gaps/resolutions reconcile against the pinned job binding. Recover the exact last proven transition and pending stage/source cursor; the old 483,895 count is not a cursor. Eight historical SQLite stores are shards of **one** supplied archive, not eight archives; 35,746 remaining rows is provisional until reconciliation.
