## SQLite no-source-write gate, before connect

`mode=ro` and `query_only` alone do **not** prove no WAL/SHM side effects. `fast_memory.MemoryStore._connect(write=False)` currently uses mode=ro and sets cache/mmap/temp pragmas but has no WAL/header gate; do not call it for this diagnostic. `sqlite_source_export.Source.open` requires a completed immutable protected view and is also unsuitable for the live file.

While holding global admission, use ordinary `O_RDONLY|O_NOFOLLOW` reads and existing no-symlink/private/single-link checks to validate each registered main file and ancestors. Freeze directory entry names plus stat tuples, main-file stat/header hash and first100 header bytes internally. Require exact SQLite header magic; read/write format bytes18/19 **1/1** (rollback format), well-formed header/page size, and absence of main `-wal`, `-shm`, `-journal` or super-journal/recovery/unexpected entries. The nine reviewed store directories currently contain only known files; do not accept a newly discovered store/sidecar. **2/2 WAL, mixed/unknown format, hot/abandoned journal, changing identity, missing file or unsupported directory shape refuses before SQLite open.** Do not chmod files, set journal mode, checkpoint, recover, create sidecars, copy files, or use `immutable`/`nolock`.

Stream a before-read whole-main-file SHA256 in64KiB chunks with time checks, without returning bytes. This is fixed unchanged-source evidence work, not an escalation after SQL refusal. Re-stat descriptor/path, reread header and entry fingerprint, then connect only if unchanged. Existing global admission serializes cooperating Castle capture/converter writers; it is not an OS ban on foreign writers. Any later change invalidates this slot's observations. No-source-write qualification requires the held admission, rollback-only gate, readonly connection/authorizer and unchanged before/after content and entry evidence together; if foreign-writer exclusion cannot be accepted for these registered sources, this direct-live diagnostic is unsupported and must not open them.

Open `sqlite3.connect(main_uri+'?mode=ro',uri=True,timeout=0.05)`. Apply only connection-local `query_only=ON,cache_size=-2048,mmap_size=0,temp_store=MEMORY,trusted_schema=OFF` before installing a strict read-only authorizer. Allow SELECT/READ, required built-in functions and read-only enumerated PRAGMAs only; deny ATTACH/DETACH, writes/schema changes, extension loading and every nonallowlisted PRAGMA/action. No user-defined function, external collation or temp table. Read-only `PRAGMA journal_mode` must report `delete`, `truncate` or `persist`; persistent-journal files are nevertheless refused by the stricter absence gate. No `=...` journal-mode operation. Recheck header/entries after connect and before first query. `BEGIN` one read transaction; first schema read establishes its view. Read `schema_version,data_version,page_size,page_count,freelist_count` in that transaction. All source queries share it.

After queries, end the read transaction by `ROLLBACK`, close SQLite, then reread/stat header, directory/sidecar fingerprint and streaming whole-main SHA256; require exact before/after content hash and stat/entry identity. Atime is excluded from the identity comparison because readonly reads may update it; size/dev/inode/mtime/ctime/mode/uid/link count are included. No source writes are issued. A change, new sidecar or a nonfinishing final hash returns `source_changed`/`unchanged_source_unconfirmed`; accumulated values are marked unaccepted and cannot establish source totals. Hashes plus all work may fail the fixed2s envelope on247–612MB files: that is a qualification failure, **not** permission to omit hashes, widen limits, manufacture a protected manifest or construct a backup. The plan has not claimed that this path fits.

## Exact SQLite operation/query sequence

All identifiers below are fixed allowlisted table/column/index names. SQLite absence detection precedes optional queries. Bound schema rows to128, tables to24, indexes to64, columns/index terms to128 each, individual schema SQL to8192 UTF8 bytes, total schema material to128KiB, and statements to96. Hash normalized schema/table/index shape inside the worker; return only counts, a fixed expected-table/index presence bitmap and SHA256 hashes. Reject unexpected application tables/unknown schema functions or shapes; recognize ordinary SQLite/FTS internal tables without querying their bodies. Use `sqlite_master(type,name,tbl_name,sql)` ordered by its fixed metadata keys and whitelisted `table_info,index_list,index_xinfo`; never echo names/SQL. Include `EXPLAIN QUERY PLAN` shape hash and numeric full-scan/temp-sort flags for the fixed aggregate families, without returning plan detail or running a different fallback. No temp sorter/body sort is allowed.

Each data aggregate operates on a deterministic primary-key prefix, cap **262,144 rows plus one overflow sentinel** per table, and a **1,048,576 total input-row allowance** for the slot. Limits and the query roster are immutable diagnostic work stops, not storage/RSS caps. Before each statement, subtract the remaining allowance and apply `LIMIT min(262145,remaining)` to its inner SELECT. A result at that bound is `prefix_only/row_limit`, with observed-prefix summaries only; stop the slot/run and do not rerun without limits. A successful aggregate with fewer rows is exhaustive for that table at this transaction's view. A progress handler every1000 VM instructions checks the shared **1.65s worker work deadline** and a fixed **10,000,000 cumulative VM-instruction allowance**; at either limit interrupt and stop. Keep the outer2s guardian unchanged. The row/VM limits do not bound single-scalar native allocation: the heap/RSS/time guards remain essential. No OFFSET, unbounded `fetchall`, whole ID array in Python or cross-store join.

The aggregate template is `SELECT count(*),<fixed numeric aggregates> FROM (SELECT <fixed columns> FROM <fixed table> ORDER BY <existing primary key> LIMIT <fixed remaining bound>)`. Do not put bodies or huge fields into ORDER BY/DISTINCT/GROUP BY. Use `COALESCE(SUM(...),0),COALESCE(MAX(...),0)` and checked nonnegative64-bit results; reject overflow/noninteger. SQL returns only numeric summaries. Primary-key fields used solely for ordering never leave SQLite. `length(CAST(field AS BLOB))` measures original UTF8 storage bytes; SQLite TEXT `length` stops at NUL and is **not** a character-count measure. Empty/null/type violations have separate counters. No canonical content hash/equality claim is made from aggregate lengths.

Within the single transaction, in this order:

1. **Schema/accounting** above. Return main bytes from metadata, SQLite page/free-page counts and derived used-page bytes; do not interpret freelist as reclaim authority or file-size difference as corruption.
2. **`chunks`, order `id`:** count, sum/max `length(CAST(text AS BLOB))`, sum/max caller/provenance byte length, min/max `start,end`, sum `end-start` for integer ordered offsets, zero-byte texts, bad TEXT/hash/ID shapes, negative/discontinuous-local bounds (`end<start`) and >8192B text count. Shape tests use bounded scalar forms; do not return IDs/hashes/text. This is lengths/shape inventory, not per-chunk SHA or global offset continuity verification.
3. **`receipts`, order `(namespace,request_id)`:** count, sum/max UTF8 byte lengths of namespace/request/digest/IDs fields, invalid/null shapes, zero/over-nine JSON membership counters, total/max JSON members. **JSON gate:** first run only byte-length/type aggregates. If any `ids` exceeds1MiB, refuse `json_membership_qualification_required` before any JSON function. For admitted rows use `json_valid` then a lazy `CASE` to call `json_type/json_array_length` only on valid array text; count invalid/nonarray separately and refuse before interpretation. No `json_each` expansion or giant IDs list in Python. The1MiB stop is proposed diagnostic allocation work scope, not a new production rejection policy.
4. **`history_occurrences`, order `identity`:** count; sum/max byte lengths of metadata, columns and IDs fields; empty-text-hash count against the fixed SHA256 of empty UTF8; invalid identity/hash/address/type counters. Apply the same prior1MiB/valid-array gate to JSON IDs, then total/max JSON members and empty-array count. `ids=[]` is only an encoding fact. No `json_extract` over metadata/columns and no text/metadata hash reconstruction.
5. **`history_occurrence_chunks`, order `(identity,chunk_id)`:** count only, plus fixed-length/type violations. Do not count DISTINCT or perform a full membership sort. A small correlated `EXISTS` query, bounded to the same occurrence-prefix allowance, counts historical owners with relational membership, owners with both forms, empty-array owners with relational members and owners with neither. Use only existing `(identity,chunk_id)` PK; if plan is not indexed, refuse before execution. The first two base aggregates determine physical member totals; **no union/dedup/equality reconciliation is claimed** from these counts. Full ordered dual-membership validation belongs to later approved reconciliation.
6. **Audit/gaps/stages**, existing tables only, their fixed PK order: count `history_attempts` and fixed `indexed/gap/other` outcomes; `history_gaps`; `history_gap_resolutions`; `history_aliases`; `history_staged_rows` with sum/max `text_bytes,text_characters,next_character,processed_bytes`, carry/metadata/columns byte lengths and fixed state counts; `history_staged_chunks` with sum/max original text bytes. Also count `checkpoints,coverage_observations,capture_chunk_scopes,capture_generation_scopes,capture_sources`, including sum/max byte lengths for their stored JSON/evidence fields and fixed scope-state counts. No derived FTS text scan. These table-row counts are **not** destination AUDIT-owner totals without checking the exporter's explicit AUDIT_TABLES rule.
7. **Existing capture coverage, live slot only:** if `capture_sources` exists and every `value` is valid JSON object <=16384B, reproduce the numeric projection from `memory_capture.coverage:346–410` in this same transaction, rather than calling that function and opening a second connection. Return observed/pending/failed sources; observed_size/processed_bytes/pending_bytes/accounting.text_bytes sums; accounting_start>0, unscoped_chunks, workspace_scope conflict/pending counts; the existing8 omission and3 exclusion counters. Validate each selected JSON numeric scalar is nonnegative integer (missing defaults0); record/refuse malformed/invalid types rather than coerce strings/booleans or throw bodies. Mark `source_currentness=last_observed_only,discovery=not_established`; scheduler JSON and zero queued in one slice do not change that. `capture_generation_scopes`/authoritative chunk mappings are only numeric counts here. No transcript/spool discovery or scope repair.

Every query reports its fixed query ID, completed/exhaustive or refused/prefix status, row count, elapsed/work count and numeric summaries. Keep per-table row allowances separate from repeated validation-pass work; charge each repeated row visitation again. Missing optional table => presence=false, not invented zero verified history. Once any resource/work/invalid-data gate refuses, do not run subsequent queries or later slots.
