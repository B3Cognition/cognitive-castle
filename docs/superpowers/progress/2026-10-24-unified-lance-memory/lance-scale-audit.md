## Minimum viable migration interface

The fixture is unsuitable as the bulk path unchanged. `LanceExactStore.import_sources` accepts ≤8 sources, constructs all records/digest/joined text in Python, and `_publish` scans every identity with `use_scalar_index=False`, validates the entire private tree, then appends records plus one replay receipt atomically (`cognitive_castle/lance_exact_store.py:94,145,187,209,313`). At least **64,956 commits** would be required for 519,641 one-chunk occurrences; actual canonical chunks, live rows and metadata add work. `lance_exact_worker.py:11,119` also caps the complete JSON input/output frame at 512 KiB. Raising the source limit alone increases copies, receipt size and replay work; its ≤9-ID receipt validation is not a bulk receipt format.

Add a separate supervised **`import_batch(batch_id, source_snapshot, cursor_start, cursor_end, expected_digest, expected_counts, bounded_spool_descriptor)`** rather than widening `remember`. A proposed initial experiment uses ≤1 MiB decoded Arrow batches, ≤256 rows per batch, and ≤16 MiB canonical payload per commit; these are candidate application bounds, not measured safe settings. The worker validates a private, no-follow, size/hash-bound local spool and streams `pa.RecordBatchReader` into `lance.write_dataset(reader, dataset_or_path, mode="append", max_rows_per_file=..., max_bytes_per_file=...)` (**L/dataset.py:5911**). A bounded spool avoids a corpus-sized parent JSON request; never accept arbitrary caller paths or let the worker launch helpers. Retain the single-writer lock and production admission/RSS/deadline limits. Each commit includes its durable batch receipt, exact membership references and cursor bounds; acknowledge only after publication. Replay verifies digest/counts and streams members, returning a bounded receipt plus membership paging rather than all IDs. `transaction_properties`/`read_transaction()` can annotate recovery, but are not a uniqueness or idempotency guarantee.

Keep canonical text, unchanged public provenance/IDs/hashes, exact occurrence metadata/columns, multiplicity and paged membership in Lance. Extend the six-column schema with typed record/descriptor/membership fields or versioned row kinds; the 1 KiB provenance limit cannot hold historical metadata. Oversized occurrences require unpublished staged pieces and a final visibility manifest, as the prior audit specifies. SQLite may retain queue/checkpoint coordination references only; it must not become canonical text/metadata fallback. A stream is not automatically a bounded transaction: cap each commit and resume, and account for manifests/fragments/orphans/index output plus retained old versions.

## Available controls and their limits

| Operation | Concrete interface in installed 4.0.1 | What remains unproven |
|---|---|---|
| Bulk append | `write_dataset` accepts `RecordBatchReader`; `max_rows_per_file`, `max_rows_per_group`, `max_bytes_per_file`; a dataset argument reuses its session (**L/dataset.py:5911–6007**). `max_bytes_per_file` is a **soft file-size** limit, checked after groups. | No documented total writer-memory cap. File/group sizes do not cap encoder buffering or native allocation. `max_rows_per_group` affects legacy format during compaction; pin/qualify the chosen storage version instead of assuming it bounds v2 RAM. |
| Identity lookup | `ds.create_scalar_index("id", "BTREE", name="canonical_id", replace=False)`; strings supported; intended for high cardinality, few rows/value (**L/dataset.py:2480–2582,2731**). Enable scalar-index use in `_find`; batch projected IDs before hydrating exact content. | No documented BTREE build-memory cap here; index is not a uniqueness constraint. Keep serialized conflict checks and duplicate detection. Appended fragments remain unindexed until maintained. |
| Lexical | `ds.create_scalar_index("text", "INVERTED", memory_limit=16, num_workers=1, ...)` is a concrete candidate experiment (**L/dataset.py:2604–2654**). `memory_limit` is **total build budget in MiB**, divided among workers; unset default is **2 GiB per worker**. `with_position=True` enables phrase queries. `scanner(full_text_query=...)` is the read path. | The FTS budget is not whole-process RSS. Low budgets produce more shards, affecting query cost. Explicitly qualify tokenizer/positions against existing matching semantics: defaults stem, remove stop words, fold accents and drop tokens over 40 characters. BM25 candidate search must not silently replace exact match behavior. |
| Vector IVF | `ds.create_index("vector", "IVF_FLAT"/"IVF_PQ", ..., shuffle_partition_batches=..., shuffle_partition_concurrency=1)`; accepted types include IVF_FLAT despite a narrower public docstring (**L/dataset.py:2885,3158–3308**). Smaller shuffle batches/concurrency trade speed for memory. Existing `ivf_centroids`/`pq_codebook` can avoid retraining. | No documented whole-build memory limit. `index_cache_size` is cache entries, not a training cap. `IndicesBuilder.train_ivf(sample_rate=..., max_iters=...)` loads `sample_rate × num_partitions` sampled vectors (**L/indices/builder.py:60–125**); raw float32 samples alone cost `4 × dimension × sample_rate × partitions` bytes, before copies/workspace. Reduced samples/partitions require recall qualification. Preserve raw vectors and input/profile mapping independently of any lossy PQ index. |
| Read bounds | `lance.dataset(..., index_cache_size_bytes=..., metadata_cache_size_bytes=..., read_params={"cache_repetition_index":False,"validate_on_decode":True})`; projected `scanner(..., batch_size=..., io_buffer_size=..., fragment_readahead=0)` (**L/__init__.py:91; L/dataset.py:4992**). | `io_buffer_size` defaults to 2 GiB and explicitly is **not a hard RAM cap**; docs warn a single larger batch can deadlock. `batch_readahead` is ignored for v2. Never use corpus `to_table()`, `to_pylist()` or `prewarm_index()` (loads the entire index). |
| Maintenance | `ds.optimize.optimize_indices(index_names=[...], num_indices_to_merge=0)` creates a delta; explicit merge later (**L/dataset.py:5657**). `compact_files(num_threads=1,batch_size=...,target_rows_per_fragment=...,max_bytes_per_file=...,binary_copy_read_batch_bytes=...)` (**5531**). Lower-level `Compaction.execute(ds, options)` exposes `max_source_fragments` via **L/optimize.py**, absent from the convenience method signature. | Index optimization's documented kwargs provide no FTS memory-budget forwarding guarantee. Compaction/index remapping still need measured RSS/disk headroom. `try_binary_copy` can fall back to reencoding; `force_binary_copy` fails on incompatibility. Stable row IDs are experimental and never replace canonical IDs/provenance. |

Fragment-level scalar builds (`create_scalar_index(..., fragment_ids=...)`) return uncommitted segments; scalar merge uses `merge_index_metadata` plus explicit `LanceOperation.CreateIndex` commit (**L/dataset.py:2591,3507**). Likewise `fragment.write_fragments(..., return_transaction=True)` plus `LanceDataset.commit` separates writing from publication (**L/fragment.py:908; L/dataset.py:3594**). Reserve these lower-level APIs for a demonstrated need: they add orphan/recovery and commit-validation obligations and do not by themselves establish bounded RAM. The documented `LANCE_BYPASS_SPILLING` switch is not a memory budget; do not enable it as an assumed safety fix.

## Narrow qualification gates

1. On synthetic private fixtures under unchanged guardian ceilings, measure streaming append/replay/crash recovery with many bounded commits, multibyte 8 KiB chunks, oversized metadata pages and late-ID reads. Record task/aggregate peak RSS, elapsed time, manifest/file count and temporary/retained bytes. Replace recursive whole-tree validation on every operation with a reviewed bounded manifest/artifact-validation boundary; retain ownership/mode/symlink/hardlink protections and do full reconciliation in maintenance.
2. Qualify BTREE build first, then indexed lookup/replay at projected chunk cardinality and fragment count. If full build exceeds limits, test bounded fragment segments/merge separately. No query-time index creation. Exercise new unindexed tails and expose index coverage/generation rather than claiming maintenance is automatic.
3. Qualify FTS with explicit low total budget/one worker, then incremental optimization and bounded compaction independently. Verify phrase/case/accent/long-token behavior and scope/policy filtering before limits. Qualify IVF only if measured scan latency/window scale demands it; compare approximate recall against bounded exact-scan truth and include appended-tail/filter cases.

**Recommendation:** implement byte-capped migration commits, canonical occurrence descriptors and paged receipts, then indexed ID lookup and explicit supervised maintenance. Keep the current archive scan as prior feasibility evidence, not a scale guarantee. Build-memory/RSS, fragment growth, oversized decode and metadata fidelity are gates; no control above justifies raising guards, rebuilding during reads or substituting SQLite canonical storage.
