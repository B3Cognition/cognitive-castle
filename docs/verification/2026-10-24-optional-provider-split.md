## Hosted timeout trigger and diagnostic correction

Retained artifacts from run `40081424011` show Linux 3.11/3.12 finished the
complete main suites successfully and recorded supervisor exit 0 at 150.5s and
184.6s. GitHub still reported their main steps running over twenty minutes later.
The runner logs locate the delay at the oversized-frame parameter in
`test_memory_protocol.py`: pytest's autogenerated test name printed the entire
megabyte payload in one line. The next tiny case only appeared at cancellation.
These were hosted log-processing delays after local test completion, rather than
a demonstrated slow assertion or model call.

Keep every frame and error assertion identical and assign the six cases short,
explicit names. Collection still produces six cases; its longest node ID drops
from 1,048,647 characters to 85. The collection-size check failed before this
change and passed afterward. Shared hardening independently fixes the reproduced
stdout-lock deadline vulnerability with lossless retained logs and bounded
console forwarding. Updated six-platform CI and the 85% union coverage gate
remain required; no timeout increase, test skip or assertion reduction is used.
